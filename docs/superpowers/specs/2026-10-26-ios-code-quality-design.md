# iOS Code Quality Campaign — Design Spec

**Date:** 2026-10-26
**Branch:** `refactor/ios-code-quality`
**Worktree:** `~/github/pwusage/.worktrees/ios-code-quality`
**Source:** maintainer review of `cmd/ios-app`; [`CODE_AUDIT.md`](../../../CODE_AUDIT.md)

## Goal

Restore a codebase that a maintainer can read, navigate, and change safely. The campaign removes
dead code, splits oversized mixed-responsibility files and view hierarchies, aligns the tree with
SwiftLint and SwiftFormat, and replaces ad-hoc cleanup with an enforced ratchet — all without
changing observable behavior.

Success is structural and verifiable:

- Every feature has one obvious home, and each file has one reason to change.
- No declaration stays in the app unless production code uses it or it is a documented dynamic
  entry point.
- SwiftLint, SwiftFormat, size budgets, and tests gate new debt in CI.
- `CODE_AUDIT.md` remains an accurate ledger of what was touched.

## Non-goals

- **No product or behavior changes.** Copy, layout, navigation, API contracts, persistence formats,
  request cadence, and error handling stay identical. Any behavior difference is a bug in this
  campaign.
- **No opportunistic correctness or UX fixes.** The `OPEN` findings in `CODE_AUDIT.md` §3–§8, §13,
  and §15 stay out of scope unless the maintainer explicitly starts a separate branch. A refactor
  PR must not be blocked for leaving them open.
- **No feature redesign or new features.**
- **No architectural replacement.** State ownership stays `ObservableObject` + `@MainActor`; the
  campaign extracts responsibilities and files, it does not introduce a new app architecture.
- **No server changes.**

## Constraints carried from the repo

- Native iOS tests use Swift Testing only (`import Testing`, `@Suite`, `@Test`, `#expect`,
  `#require`). — `AGENTS.md`
- Every native test run goes through `cmd/ios-app/run-tests.sh`; never invoke `xcodebuild test`
  directly. — `AGENTS.md`
- The test target is generated by `xcodegen`; never hand-edit `PWUsage.xcodeproj`. New files are
  picked up because `project.yml` uses path-based sources.
- The build must stay at **zero Swift compiler warnings**.
- `DEVELOPMENT_TEAM: 6HQGHHRK87` stays committed in `project.yml`. — `AGENTS.md`
- No `any`; explicit types for parameters and returns. — `AGENTS.md`
- The app is phone-first but supports adaptive layouts; behavior-preserving means the existing
  size-class and accessibility behavior is preserved, not simplified.
- `git status` in the main checkout has unrelated Next.js changes. All campaign work happens in
  this worktree and is committed only here.

## Decisions settled with the maintainer

### D1 — Behavior-preserving refactor only

The campaign may move, split, merge, and delete code, but not alter behavior. This keeps every PR
reviewable against tests and makes rollback trivial. Correctness findings remain separate work.

### D2 — Split by feature, keep current layers

Keep `Views/`, `State/`, `Models/`, `Networking/`, `Navigation/`, `Authentication/`, plus `Shared/`
and `PWUsageWidgets/`. Split multi-type files and introduce feature subfolders where a screen owns
several supporting types. This buys SRP readability without a repository-wide move that would make
history and review harder.

### D3 — Ratchet to zero, fix by rule

Adopt a checked-in SwiftLint baseline immediately so CI blocks new violations while the old ones
are burned down rule-by-rule. The baseline is removed when it reaches zero. It is never regenerated
to absorb new debt.

### D4 — Approved tooling

- SwiftLint baseline + blocking CI.
- SwiftFormat for mechanical fixes, with a pinned config.
- Periphery for dead-code discovery, initially local-only.
- Explicit size and complexity budgets, lowered as features are cleaned.

### D5 — Sequencing: gate first, then feature sweep

1. Enforcement and mechanical lint.
2. One feature at a time, in dependency order.
3. Final budget tightening and blocking gate.

This avoids a second pass over every file and prevents the tree from re-acquiring the debt that was
just removed.

## Design — Enforcement and tooling

### SwiftLint

- Check in `.swiftlint-baseline.json` generated from the tree at the tooling PR's commit.
- CI runs `swiftlint lint --strict --baseline .swiftlint-baseline.json` from the repository root.
  Remove `continue-on-error`.
- Local runs use the same command; no separate local policy.
- Keep the existing opt-in rules (`sorted_imports`, `empty_count`, `force_unwrapping`,
  `unhandled_throwing_task`) and add the cleanup rules that encode this campaign:
  `file_length`, `type_body_length`, `function_body_length`, `cyclomatic_complexity`, `nesting`,
  `large_tuple`, `function_parameter_count`, `unused_declaration` where reliable.
- Start at default thresholds (120 columns; file 400 warning / 500 error; type body 350/450;
  function body 60/100; complexity 10/15; nesting 1/2; large tuple 3/4; parameters 5/8). Relax a
  rule only when an entire category is legitimate project style, never per file.
- No file-wide suppressions. A `swiftlint:disable` must be `:next` and carry a reason.
- Regenerate the baseline only in a PR that removes violations. Review the violation-count delta in
  that PR.
- Lower budgets only after the relevant subtree is clean, so the ratchet is monotonic.

### SwiftFormat

- Add a root `.swiftformat` scoped by invocation to `cmd/ios-app`:
  `--swiftversion 6.0`, `--maxwidth 120`, sorted imports, trailing commas, consistent whitespace.
- Add `cmd/ios-app/format.sh` as the documented wrapper.
- Formatting-only changes land in their own PRs and are recorded in `.git-blame-ignore-revs`.
- CI runs `swiftformat --lint cmd/ios-app` once the mechanical pass lands; semantic edits remain
  hand-written.

### Periphery

- Add `cmd/ios-app/.periphery.yml` covering `PWUsage`, `Shared`, and `PWUsageWidgets`.
- Run locally during each feature sweep. Do not add it to CI until its false-positive rate for
  SwiftUI previews, WidgetKit, ActivityKit, App Intents, and Control Center entry points is
  measured.
- A declaration is deleted only when Periphery, a symbol grep, and the compiler agree.
- Retained dynamic entry points get a short reason in the PR; use Periphery's ignore mechanism
  rather than a broad config exclusion.

### PR separation

- PR 1: tooling (baseline, CI gate, SwiftFormat config/wrapper, Periphery config, budget rules at
  current values).
- PR 2…n: mechanical rule sweeps only, grouped by rule family.
- PR n+1…: one structural PR per feature.
- No PR mixes mechanical formatting with semantic or structural edits.

## Design — Feature sweep

### Order

1. **Foundation** — `PWUsageApp` split into launch/bootstrap, root view, commands, and empty state;
   `app-tab-view`; shared chrome (`SectionTheme`, `portable-modifiers`, `clipboard`) and one shared
   `CardContainer`; small shared primitives (`AvailabilityBanner`, `EmptyCard`, loading state);
   `Shared/app-configuration`, `Shared/shared-web-session`, and the neutral parts of
   `Shared/mobile-live-contract`. Unblocks every later feature and removes the three duplicated
   card containers (`CODE_AUDIT §9.10`).
2. **Home / Dashboard + Today's Energy** — `DashboardView` supporting views,
   `DashboardCoordinator` split by refresh/polling/cache/presentation, `DashboardPresentation`,
   `DashboardCache`, `EnergyBalanceChart`, `EnergyFlowProjection`; `Shared/today-energy-*` and
   `PWUsageWidgets/today-energy-*`.
3. **Load Timing + Smart Shift** — `LoadTimingView` split into screen, freshness label, detail
   sheet, and card; `LoadTimingForecastPresentation`; `LoadTimingForecastEstimator` split into
   estimation/forecast/bounds; `LoadProfile`, `LoadProfileStore`, `LoadProfilesSheet`;
   `SmartShiftPresentation`, `SmartShiftDetailsView`, `SmartShiftCostBars`,
   `SmartShiftDiagnostics`.
4. **Battery Saver** — `battery-hold-*` views, state, and models; activity coordinator/host;
   `Shared/battery-hold-*`; the Battery Saver widget/Live Activity surface.
5. **Solar Forecast** — `SolarForecastStore` split into persistence, credential/keychain,
   network/budgeting, and failure-classification types; `SolarForecast`, `SolcastClient`,
   `SolarForecastSettingsSheet`, `SolarForecastSettingsStatus`, `SolarForecastPreviews`.
6. **Bill + Tariff** — `BillView`, `BillOutlook`, `BillOutlookPresentation`, `MobileTariffs`,
   `TariffSheet`.
7. **Auth + Settings + Sites** — `MobileAuthService` split into session/bootstrap/sign-in
   responsibilities; `SignInView`, `settings-view`, `SitePickerView`, `about-sheet`,
   `app-launch-maintenance`.
8. **Tests + ledger** — split oversized test files to mirror features, move shared spies/fakes to
   `PWUsageTests/Support/`, pin locales, fix misnamed suites; regenerate a smaller baseline, lower
   budgets to target, remove the baseline file, make every gate blocking.

### Per-feature workflow

1. **Map** — inventory types, owners, callers, file sizes, and view hierarchy. Record the feature's
   target file split and the `CODE_AUDIT` rows it will touch in the PR description.
2. **Characterize** — add tests first where logic being moved lacks coverage. Pure presentation
   moves should be covered before they move; view-only extraction relies on existing render tests
   and the smoke matrix.
3. **Delete** — remove unused declarations, preview-only code from the release target, orphaned
   models, empty or duplicate helpers when the audit's documented exceptions do not apply.
4. **Split** — one screen type per file; supporting subviews and presentation in named files under
   a feature subfolder; pure presentation separated from SwiftUI; coordinators and actors split by
   responsibility. Preserve `@MainActor` ownership and observable boundaries.
5. **Verify** — build, full tests, render tests, SwiftLint with no new violations, SwiftFormat lint,
   Periphery clean for touched targets, and the feature's manual smoke matrix.
6. **Ratchet** — lower the feature's size/complexity budgets once clean and update the matching
   `CODE_AUDIT` rows in the same commit.

### Test cleanup

- Split test files to mirror production feature boundaries; rename suites that do not match what
  they test (for example the current `LoadTimingViewTests` file, which tests presentation types).
- Move the three dashboard spies and two auth fakes into one configurable double per protocol under
  `PWUsageTests/Support/` (`CODE_AUDIT §9.14`).
- Pin locale and time zone in assertions that currently rely on `Locale.current`.
- Keep Swift Testing and `eventually`/`staysTrue`; no fixed sleeps.
- Test files get the same budget ratchet as production files.

### Documentation

- `CODE_AUDIT.md` stays the live ledger. Every finding touched is updated in the same commit, with
  re-derived line numbers; section numbers never change.
- Add `cmd/ios-app/ARCHITECTURE.md` describing folder conventions, ownership rules, budgets, and the
  sanctioned dynamic entry points that Periphery must ignore.
- Record the final violation count and budget values in `CODE_AUDIT.md §14.4`.

## Verification

Every PR:

```bash
cd cmd/ios-app && ./run-tests.sh
xcodebuild -project cmd/ios-app/PWUsage.xcodeproj -scheme PWUsage \
  -destination 'generic/platform=iOS Simulator' CODE_SIGNING_ALLOWED=NO build
swiftlint lint --strict --baseline .swiftlint-baseline.json
swiftformat --lint cmd/ios-app
```

Plus Periphery for touched targets during feature sweeps.

Behavior-preservation guardrails:

- No string, layout, navigation, request, or persistence changes. Strings stay byte-identical.
- Characterization tests land before moving untested logic.
- Existing render tests are the UI guard; the manual smoke matrix covers launch, sign-in, refresh,
  stale/empty/error states, rotation/size classes, and widget/Live Activity surfaces where relevant.
- A behavior difference found during review stops the PR and becomes its own investigation.

## Risks and mitigations

| Risk | Mitigation |
| --- | --- |
| Baseline hides regressions | Regenerate only in violation-reducing PRs; review the count delta; never relax a budget without a clean subtree. |
| Formatting churn obscures history | Formatting-only PRs; `.git-blame-ignore-revs`; no semantic edits in those commits. |
| Periphery false positives delete live code | Require Periphery + grep + compiler agreement; document dynamic entry points; keep it out of CI until measured. |
| Project file drift | `xcodegen` path-based sources; never hand-edit the generated project. |
| Splits introduce state or ownership bugs | Preserve actor/main-actor boundaries; characterization tests first; one feature per PR. |
| Parallel branches conflict | Sequence behind open iOS PRs; rebase one feature at a time. |
| SwiftUI preview/entry-point analysis is incomplete | Treat previews and system entry points as retained unless proven otherwise; list them in `ARCHITECTURE.md`. |

## Exit criteria

- SwiftLint baseline is empty and deleted; the CI step is blocking and clean at `--strict`.
- SwiftFormat lint is blocking and clean.
- Size/complexity budgets are at target values: file 400/500, type 350/450, function 60/100,
  complexity 10/15, nesting 1/2, large tuple 3/4, parameters 5/8 — or a documented, category-wide
  exception.
- Periphery reports no unused declarations for app, shared, and widget targets, with documented
  dynamic exceptions.
- `./run-tests.sh` passes; test files mirror feature boundaries; shared doubles live in
  `PWUsageTests/Support/`.
- `CODE_AUDIT.md` and `cmd/ios-app/ARCHITECTURE.md` reflect the final state.
- No PR in the campaign changes observable behavior.

## Rollback

Each PR is independently revertable, contains no generated project changes, and never depends on a
later PR to compile. The worktree branch is isolated from `main`; nothing lands until the
maintainer opens a PR.
