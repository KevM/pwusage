# Compact archive trim and recovery primitives implementation plan

**Goal:** Prove archive-preserving raw trimming and lossless restoration before late corrections, without exposing or enabling production trimming.

**Architecture:** A generated `raw_pruned` archive marker makes the archive authoritative after verified per-day trimming. Trim requires the reviewed revision, verified compressed/decoded chart, summaries, coverage/latest projections, complete tariff attribution and the existing editable-day buffer; it locks the site and verifies raw parity before deleting. Insert/update into pruned days and timezone changes with pruned archives fail closed in database triggers. Archive-aware batch writers restore every touched pruned day from its verified archive, then apply the incoming partial batch in the same transaction. Explicit restoration is bounded to one reviewed day and removes the old archive only after recovering samples transactionally. No custom setting/trigger disabling bypass, CLI trim, cron or switch activation.

1. Write failing real PostgreSQL tests: preserved archive/summary/revision/read parity after trim, stale-revision/recent-day/corruption/incomplete-attribution refusal, retry, lossless restore, blocked direct insert/timezone change, late partial import preserves untouched samples/SOC, failed incoming write rolls back restoration, contention and bounded egress. Add opt-in repository delegation tests with default behavior retained.
2. Generate migration; replace invalidation functions to protect pruned days while keeping unpruned semantics. Implement lock-ordered trim/restore/batch primitives in CompactHistoryStore, verified recovery helper and bounded inserts. Stage batch delegation behind the existing read switch.
3. Ensure finalization refuses to treat a pruned day as empty; verify/return unchanged if archive-only source remains valid. Maintenance scalar coverage includes verified pruned-day coverage and refuses --rebuild until restored, avoiding silent partial reconstruction.
4. Independent review, full tests/lint/build and local fixture removal. Document operational gates and update local draft PR scope; commit. No production trim or paid Tesla repair. Operator exposure still needs first-trim approval/backup evidence and a complete rollback/restoration plan.

Implementation evidence: PostgreSQL canonical binary sample digest proves exact parity without raw rereads, including signed zero. Direct mutation/timezone guards also reject a damaged unpruned marker with incomplete raw source. Finalization refuses to rebuild that partial source. Pruned maintenance reports archive coverage and refuses raw rebuild. Ten backup days (2,859 samples) passed trim/read/restore/partial-correction parity; aggregate response costs and operational rollback gates are documented in the maintenance guide.
