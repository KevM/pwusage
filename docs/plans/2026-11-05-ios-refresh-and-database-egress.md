# iOS Refresh and Database Egress Implementation Plan

**Goal** — A pull on Home, Bill, or Smart Shift checks for fresh Tesla data immediately and updates the screen when new history lands. Repeated pulls keep PostgreSQL transfer bounded.

**Architecture** — Keep live power on the existing fast endpoint. Let the mobile summary request ask for history independently of the automatic cadence, then reuse energy and billing calculations when their stored inputs are unchanged. Keep authorization and import ownership at the server.

**Stack** — SwiftUI, Swift Testing, Next.js route handlers, Vitest, and PostgreSQL day records.

## Where repeated pulls cost database egress

- **Fast power** performs authorization, a narrow live cache read, credential lookup and, on success, a cache write. The write invalidates the site cache on its instance. Measure this path before changing its cadence or cache policy. [Live refresh service](../../cmd/next-app/src/lib/today-refresh.ts#L211), [site cache write](../../cmd/next-app/src/lib/site-repo.ts#L456)
- **The summary** reads today's compressed archive and summary rows to produce buckets. It can read the archive again after a successful import and separately for today's exact tariff cost. The history floor sits after the first read. A throttled import therefore still incurs summary egress. [Summary route](../../cmd/next-app/src/app/api/site-live-data/route.ts#L55), [day archive read](../../cmd/next-app/src/lib/prototypes/compact-history-store.ts#L86)
- **The bill** uses `outlook=1`, which reads completed-day aggregates and coverage plus today's detail. A Bill or Smart Shift pull can calculate the bill before and after import even when history did not advance. The importer itself can replace a day record on a newer fetch with identical samples, including reading tariff data for the write. `no-new-rows` is based on whether a newer timestamp was persisted and does not prove the stored content is identical. [Bill refresh](../../cmd/ios-app/PWUsage/State/Home/DashboardCoordinator+LoadTiming.swift#L143), [bill computation](../../cmd/next-app/src/lib/energy-repo.ts#L261), [day writer](../../cmd/next-app/src/lib/prototypes/compact-history-store.ts#L290)

## 2. Make the manual history result explicit

- Start in `site-live-data/route.ts`, `today-refresh.ts`, `import-lock.ts`, and the importer. Remove the 15-second floor on the explicit mobile gesture path once the egress checks in Step 4 are met. Keep the normal atomic lease acquisition and owner-checked release, including timestamp restoration on failure. Preserve deadlines, automatic cadence and backoff, Tesla reconnect behavior, and the web/TRMNL policies. Keep a successful attempt's timestamp semantics for automatic callers unless the baseline shows a new lockout.
- When a pull meets an active import, share the result where possible. Across instances, use a bounded check for completion and return an explicit pending outcome if the lease outlasts the request. Let the client make one follow-up check while the same site is visible. This avoids both silently dropping a pull and starting a second writer. A pull that overlaps a regular read should reuse the summary work when it already performed the relevant history check.
- Carry an optional refresh outcome in the mobile live contract and its Swift mirror. Distinguish history changed, already current, awaiting Tesla data, import pending, and refresh failed. Keep the observed sample timestamp separate from the time of the check. Preserve compatibility with clients and servers that omit the field.
- In `DashboardCoordinator+Refresh.swift` and `DashboardView.swift`, let a long foreground return revalidate missing or over-hour energy once when scheduled work would otherwise leave it stale. Deduplicate with the timer and any existing request. Keep a completed-attempt retry cadence during outages. Tie the banner to the outstanding refresh for the current site and show which reading remains unavailable after it settles. Treat a legitimately empty morning differently from a failed or blocked import. Keep cached values and their original timestamps when offline.

## 3. Bound repeated database reads

- Before reloading archive payloads, check a narrow history version for the relevant day or billing cycle. Reuse existing day-record metadata where it can identify a changed input across instances. The version must account for corrections to existing sample times, backfills, tariff changes, site-local day/cycle rollover, and billing settings. Compare content and attribution before rewriting an unchanged day while preserving fetch/finality metadata. A later `fetched_at` alone should never trigger a full recalculation.
- In the mobile summary, reuse one day detail read for the displayed totals and exact tariff cost where possible. After import, reread only if the result will otherwise miss a committed change. Let the app send the opaque version of its saved summary or bill. If the version still matches, return a lightweight unchanged result and reuse the saved calculations. Evaluate time-sensitive tariff and forecast presentation separately so it can advance without a new energy sample. Perform access checks before reuse and scope saved responses to their authorized site. Test unchanged requests against a cold serverless instance so the savings hold across instances.
- In `DashboardCoordinator+LoadTiming.swift`, display the existing bill immediately while the check runs. Fetch when there is no usable bill or when the result reflects a new energy or tariff revision. Recalculate once if the first result preceded the changed history. Keep Smart Shift's explicit forecast refresh and its separate planning-context cache. Keep the shared bill current on Home, which also displays it.

## Review changes to this plan

Review of the implementation changed two details. One follow-up at two seconds often ran before the import finished, so a pending import now gets up to three read-only checks over about 10 seconds, then the five-minute summary interval. `awaiting-data` now applies only in the first hour after site-local midnight. Later, an empty day reports `overdue` and Home shows the general refresh prompt.

## Local egress results and rollout gate

Run `bash scripts/test-mobile-route-egress.sh` from `cmd/next-app`. It starts isolated PostgreSQL, seeds archived and open days, and sends deterministic Tesla responses through the real import service. The fixture opts into `MOBILE_MANUAL_IMPORT_NO_COOLDOWN=true`. It verifies that consecutive manual pulls reach Tesla within 15 seconds, the import lease still excludes other writers, and unchanged responses skip archive detail.
